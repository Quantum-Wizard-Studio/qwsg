# Core Alpha Architecture Gate Register

Open gates remain owner or later-task decisions. A recommendation is not ratification.

| ID | Gate | Why open and what it blocks | Options and decision criteria | Slice 1 implementation |
| --- | --- | --- | --- | --- |
| `AG-001` | Supported platform matrix | Exact Ubuntu/Debian versions and CPU architectures lack approval and tests; blocks supported-platform claims and release. | Choose narrow tested combinations based on security support, CI/test access, kernel/init variance, and packaging feasibility. | May proceed with adapters/fixtures; no support claim. |
| `AG-002` | E-mail transport | Local submission versus authenticated SMTP is unresolved; blocks complete Core Alpha alerts and release. | Evaluate privilege, secrets, offline behavior, delivery diagnostics, and testability. | Not needed. |
| `AG-003` | Retention and storage budgets | Duration/size policy is owner-controlled; blocks production persistence cleanup and release. | Decide per data class using operator value, privacy, disk bounds, export, and active-incident safety. | May keep transient or latest-only state if authorized. |
| `AG-004` | Console security and sequencing | Authentication, authorization, recovery, session, exposure, and first-release inclusion are unresolved; blocks network Console. | Decide local-only/reverse-proxy/standalone models based on identity recovery, least privilege, TLS, audit, and Agent independence. | Proceed without Console/network transport. |
| `AG-005` | Update authenticity and signing | No trust root, signing, distribution, rotation, or recovery policy; blocks update implementation and supported distribution. | Define signed artifact/metadata scheme, offline verification, key custody/rotation/revocation, rollback protection. | Not needed. |
| `AG-006` | Runtime and packaging | No language, dependency, service topology, package, build, or reproducibility choice; blocks Task 009 coding until its preflight decision. | Compare memory/disk footprint, safe subprocess/filesystem APIs, schema tooling, distro packaging, dependency locking, maintenance, and test ecosystem. | Must be decided at Task 009 start; architecture stays neutral. |
| `AG-007` | Configuration syntax and secrets backend | Full Core Alpha activation and notification secrets need concrete formats and permissions. | Choose strict schema, atomic activation, clear precedence, protected references, rotation, backup/export behavior. | Slice 1 may use minimal non-secret validated configuration; no secret backend. |
| `AG-008` | Durable store technology | Restart continuity and history require locking, atomicity, migrations, corruption behavior; retention is also open. | Evaluate embedded database versus bounded files using crash safety, migrations, query needs, footprint, backup, and recovery. | Optional latest-envelope adapter only; not required for initial collector core. |
| `AG-009` | Commercial, licensing, telemetry, cloud | Product Definition leaves business and distribution policy open; blocks public distribution/claims. | Owner decision with legal, ethical, privacy, support, and sustainability review. | No effect on internal implementation; no telemetry/cloud. |
| `AG-010` | Legacy governance and permission anomalies | Task IDs/slugs and mode `0600` records are inconsistent; blocks clean collaboration/audit automation, not product design. | Approve legacy alias rules and future mode policy without rewriting history. | May proceed; disclose limitations. |
| `AG-011` | Partial-result CLI exit policy | Functional exit classes do not explicitly assign mixed success; blocks a stable CLI contract. | Prefer a documented non-zero incomplete result or machine-visible completeness plus a stable exit mapping; criterion is no false success and scriptability. | Must be decided in Task 009 contract work. |

Previously disclosed release gates remain open unless explicitly covered above. No gate is closed by this document.
